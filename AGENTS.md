# Time Tracker: инструкции для Codex

## Контекст проекта

- Это локальный трекер времени на React 18, TypeScript и Vite.
- Десктопная оболочка находится в `electron/` и использует Electron.
- Состояние приложения хранится через React Context + `useReducer`.
- Пользовательские данные сохраняются в `localStorage` под ключом
  `time-tracker-v1`. Не ломайте совместимость сохранённых данных без явной
  миграции в `src/lib/storage.ts`.
- Подробное описание структуры, релизов и поведения находится в `README.md`.

## Основные команды

```bash
npm install
npm run dev
npm test
npm run build
npm run app
npm run app:dev
```

- После изменений кода всегда запускайте `npm test` и `npm run build`.
- Отдельного lint-скрипта сейчас нет.
- Для ручной проверки веб-интерфейса используйте `npm run dev`.
- Для проверки Electron в режиме разработки сначала запустите Vite, затем
  `npm run app:dev`.

## Архитектура

- `src/state.tsx` — глобальный store, reducer и персистентность.
- `src/types.ts` — модели клиентов, проектов, задач, записей и настроек.
- `src/lib/money.ts` — ставки, биллинг, валюты и форматирование сумм.
- `src/lib/time.ts` — время и календарные функции.
- `src/lib/storage.ts` — валидация, загрузка, сохранение и миграция данных.
- `src/screens/` — экраны приложения.
- `src/components/` — переиспользуемые UI-компоненты.
- `src/popover/` — интерфейс popover меню-бара macOS.
- `electron/main.cjs` — главный Electron-процесс, tray и обновления.
- `electron/preload.cjs` — безопасный мост между Electron и renderer.

## Бизнес-инварианты

- Ставка записи: `task.rate ?? project.rate ?? settings.globalRate`.
- Валюта: `project.currency ?? settings.currency`.
- Длительность для биллинга округляется вверх до интервала из настроек.
- Суммы разных валют в отчётах не складываются.
- Старт нового таймера останавливает и сохраняет предыдущий.
- Записи короче одной секунды не сохраняются.
- Активный таймер должен корректно восстанавливаться после перезапуска.

## Ограничения изменений

- Сохраняйте текущие визуальные паттерны и адаптивность интерфейса.
- Не меняйте версию, теги, release-конфигурацию и GitHub Actions без явного
  запроса на релиз.
- Не коммитьте `node_modules/`, `dist/`, `release/`, `.claude/` и локальные
  файлы среды.
- При изменении IPC синхронно обновляйте `electron/preload.cjs`,
  `electron/main.cjs` и типы renderer в `src/desktop.d.ts`.
- При изменении таймера проверяйте главное окно и popover меню-бара.

## Критерии готовности

- `npm run build` завершается успешно.
- `npm test` завершается успешно.
- Существующие пользовательские данные остаются читаемыми.
- Основные сценарии таймера, ставок, отчётов и экспорта не регрессируют.
- Изменения ограничены задачей и не включают случайные release-артефакты.
